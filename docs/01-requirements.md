# 项目题 2：需求与成功标准

## 用户与目标

内容运营输入主题、预算与截止时间，获得预算与时间约束内的内容活动方案。

## 输入与资料

必填：request_id、主题、预算、截止时间（含时区）。预算使用模拟单位，以整数最小单位计算，避免浮点误差。合成资料包含素材、可选制作方式、工具费用与耗时；具体规则见data/catalog.json；最终报价变化场景见data/quote-change.json。

缺少预算或截止时间时返回 needs_input 和待补字段，不推断默认预算或期限，不执行收费工具。预算非法、截止时间已过等情况返回明确输入错误。

## 最小范围

提供素材检索、脚本生成、成本估算、方案保存四种工具。输出任务计划、各步骤实际状态、工具结果、费用合计、保存标识，或明确未完成原因与缺口。

模型必须经历选择动作、工具执行、结果观察、调整下一步或结束的循环。遇到超预算、工具失败或部分成功时，模型可选择替代方案、重试失败步骤或停止；成功结果保留，失效依赖需明确标记。

## 验收矩阵

| 场景 | 预期 |
|---|---|
| 正常完成 | 依赖满足，费用与预计耗时合规，保存成功后才标记完成 |
| 缺预算或截止时间 | 明确列出缺失字段，无保存行为 |
| 工具失败 | 失败步骤标记失败，保留已成功结果，模型调整或返回未完成 |
| 预算超限 | 初始估算 12、预算 10 时尝试可行替代方案 8；无可行方案则说明缺口 |
| 重复执行 | 相同 request_id 和输入返回已有结果，不重复保存；输入不同返回冲突 |
| 达到调用上限 | 返回 incomplete 及已成功步骤、终止原因 |
| 时间超限 | 尝试耗时更短方案；不可行则说明时间缺口 |

失败步骤续跑为可选加分项，不纳入首期必须实现范围。截止时间按当前时间加剩余步骤耗时估计校验；估计不代表真实生产交付保证。

## 非目标

不实现真实发布、真实支付、素材版权审核、排期日历、复杂权限、界面、线上部署或多 Agent。


## v0.2 交互需求

提供终端对话入口，启动说明支持文件、推荐输入及默认选择。自然语言抽取主题、预算和期限，缺少关键约束时追问；先显示摘要，用户/run后才执行业务工具。相对日期以当前北京时间解析。模糊期限不默认具体时刻。

附加UTF-8文本说明或结构化JSON素材库；限制大小、数量和结构，拒绝重复素材ID。附件内容摘要参与请求指纹，避免相同请求编号换素材后错误重放。未提供的内容形式由模型根据约束选择，结果明确展示。保留原JSON批处理入口。
