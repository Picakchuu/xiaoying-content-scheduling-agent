# 基本架构（待实现）

## 模块边界

CLI → 输入校验 → 状态读取 → Agent 循环 → 工具分发 → 本地工具与存储。

- 模型适配：统一真实模型和离线 Mock 的结构化动作接口。
- Agent 循环：把当前计划、已完成结果和工具观察交给模型，执行合法动作，再更新状态。
- 工具层：search_materials、generate_script、estimate_cost、save_plan。
- 状态层：保存请求指纹、计划版本、步骤状态、成功结果、费用与 Trace。

不预先限定检索后的唯一工具序列。模型可根据观察重新检索、生成替代脚本、重新估算或结束；执行器负责校验依赖和约束，不代替模型选择方案。

## 状态与约束

任务状态：needs_input、running、completed、incomplete、failed。步骤状态：pending、running、succeeded、failed、skipped、invalidated。整体状态与步骤状态分开保存。

保存依赖当前版本的素材、脚本、估算结果；方案变化使相关估算失效，必须重新估算。仅当当前方案预算、截止时间和依赖均通过校验，才允许保存。保存成功后才能返回 completed。

费用分开记录：方案预计总费用与实际工具调用累计费用；最终预算检查覆盖执行已花费用及方案尚需费用，避免重复计费。估算规则须说明哪些费用已包含。失败调用是否收费由工具返回与规则表决定，不假设失败免费。

相同请求标识与输入指纹返回已有记录；不同指纹拒绝覆盖。保存工具采用唯一请求键避免重复方案。保存结果不明确时先查询存储记录。

## 循环与错误

设置有限的模型轮次及工具调用上限，具体默认值由实现确定。无效动作、工具异常也计入相应上限，禁止无限重试。工具返回结构化成功、部分成功或失败，以及可保留结果和错误类型。

Trace 记录步骤、动作、工具参数、返回摘要、后续动作和简短依据，不记录模型内部思维过程。模型输出仍须由执行器校验。

离线 Mock 仅用于流程测试，不能证明真实模型决策效果。当前未选择框架；若使用框架须补充版本、使用功能及职责。
